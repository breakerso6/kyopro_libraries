# BeamSearch 利用例とTODOひな型

[APIドキュメント](../../docs/algorithm/BeamSearch.md) · [アルゴリズム一覧](../../docs/algorithm/README.md)

各ファイルは標準ヘッダ・問題側の型・入力・探索呼び出し・出力・`main` を含む独立したプログラムです。共通の問題側ヘッダは使わず、ファイル単体で書く量を比較できるようにしています。[BeamSearch.hpp](../../libraries/algorithm/BeamSearch.hpp) を利用し、6つの具体例はそのままビルド・実行できます。TODOひな型は問題固有の処理を埋めてから使ってください。

リポジトリルートでのビルド例です。

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -I. \
  examples/beam_search_draft/01_copy_fixed.cpp -o /tmp/beam_copy
/tmp/beam_copy < input.txt
```

## TODOを埋めるひな型

| ファイル | 問題に応じて実装する内容 |
| --- | --- |
| [template_copy.cpp](template_copy.cpp) | 入力・初期状態・操作・合法手・適用・評価・出力 |
| [template_tree.cpp](template_tree.cpp) | コピー版と同じ項目に加えて、操作の取り消しと復元用データ |

どちらも、最初はkeyなしの通常ビームを指定しています。`policy` の差し替え例をコメントで併記しているため、同じひな型からkey別・全体＋key別・chokudaiへ切り替えられます。

1. `Action`、`State`、入力と初期状態を定義する。
2. `legal_actions()`・`apply()`・`evaluate()` のTODOを埋める。木上版は `undo()` も実装する。
3. `max_depth` と幅を設定する。key別の場合は `Info` の `Key`・`key` のコメントを外し、`evaluate()` でkeyも設定する。
4. `policy` は一つだけ宣言する。chokudaiでは時間または展開数の予算も設定する。
5. 操作列の出力と、完了解が未発見の場合の処理を実装する。

`legal_actions()` と `evaluate()` は、このひな型で処理を分けるための問題側ヘルパーです。ライブラリが必須とする関数ではありません。速度を詰める場合は `expand()` 内で直接合法手を列挙して `emit` し、中間の `vector<Action>` や評価の全計算を省けます。

木上版は、まず `apply → evaluate → undo → emit` で書き始める形です。評価情報を差分だけで計算できる問題では、既存の具体例のようにStateを変更せず候補を生成できます。

ひな型の空の `Action`・`State`、候補0件の列挙、コスト0の評価、最大深さ0は未記入箇所です。そのまま有効な解法になるものではありません。通常ビームの時間制限はコメントアウトし、固定手数の最終層へ到達する前に打ち切らない設定にしています。

## 問題設定

`H × W` のグリッドの左上から始め、ちょうど `T` 手の間、上下左右への移動または待機を行います。グリッドの外へは出られません。

- 各マスには非負の得点があります。初めて訪れたときだけ獲得します。
- 開始地点の得点は最初から獲得済みです。再訪問・待機では得点が増えません。
- 得点の合計を最大化します。ライブラリには `cost = -score` を渡します。
- 全マス回収後も待機などで `T` 手まで進めるため、`finished` は常に `false` とします。

### 入力

```text
H W T
a[0][0] ... a[0][W-1]
...
a[H-1][0] ... a[H-1][W-1]
```

制約は `H >= 1`、`W >= 1`、`H * W <= 25`、`0 <= T <= 100`、`0 <= a[y][x] <= 1000000` です。訪問済み集合を32bit整数で持ち、現在位置と組み合わせて衝突しないハッシュを作ります。この例ではコピーするStateが小さいため、木上版が高速になるという主張ではありません。

### 出力

1行目に獲得得点、2行目に長さ `T` の操作列を出力します。操作は `U`、`D`、`L`、`R`、`.`（待機）です。`T == 0` の2行目は空行です。

探索が時間・展開数上限に達し最終解が未発見なら、全手を待機にする有効な解を返します。`partial` は手数が足りないためそのまま出力しません。各例は近似探索であり、最適解を保証しません。

## 6つのプログラム

| ファイル | 状態の保持 | 探索と選抜 |
| --- | --- | --- |
| [01_copy_fixed.cpp](01_copy_fixed.cpp) | コピー | 通常の固定幅100。keyの型・メンバなし |
| [02_tree_fixed.cpp](02_tree_fixed.cpp) | 木上差分更新 | 通常の固定幅100。`apply`・`undo` を追加 |
| [03_copy_keyed.cpp](03_copy_keyed.cpp) | コピー | 各位置の上位3件ずつ |
| [04_tree_global_plus_keyed.cpp](04_tree_global_plus_keyed.cpp) | 木上差分更新 | 全体上位100件＋残りから各位置の上位2件 |
| [05_copy_chokudai.cpp](05_copy_chokudai.cpp) | コピー | 各走査・深さで1件展開、全体上位1000件を保持。keyなし |
| [06_tree_keyed_chokudai.cpp](06_tree_keyed_chokudai.cpp) | 木上差分更新 | 各走査・深さで各位置1件展開。全体上位1000件＋各位置追加20件を保持 |

全例で `max_depth = T`、時間上限0.2秒、最大展開数20000を指定します。再現性のある比較をしたい場合は `time_limit_sec` の代入を削除し、展開数を揃えてください。

### コピー版と木上版の違い

コピー版は次のStateを作り、操作文字と評価情報を `emit` します。木上版はStateを生成せず、操作に移動元・移動先・初訪問かどうかを記録します。`undo` は、その操作で初めて訪れた場合だけ訪問済みビットを消すため、以前の訪問を誤って取り消しません。

木上版の評価では現在コストから獲得得点を引き、訪問済みビットを仮に足すだけで次の `Info` を生成します。`expand` 中にStateを変更する必要はありません。スコアとkeyは `Info` から扱うため、`apply`・`undo` で更新する対象も減っています。

### 通常版とkey別版の違い

通常版の `Info` に `Key`・`key` はなく、`FixedBeam` の専用経路を使います。key別版は `Info::key = pos` とするだけで、現在位置ごとに探索枠を確保します。移動すると子のkeyも変わります。

この問題では得点は訪問済み集合から決まるので、同じ深さ・現在位置・訪問済み集合なら、その後の遷移も含めて同一視できます。経路の順序そのものはハッシュに含めません。

## 入出力例

```text
3 3 4
1 2 3
4 5 6
7 8 9
```

この入力で6例とも、次の得点・経路を返すことを確認しています。時間制限のため、異なる実行環境で同じ探索量になる保証はありません。

```text
29
DDRR
```

開始地点の1点に、下・下・右・右の順で4・7・8・9点を加えます。

## 確認範囲

6例を実際のヘッダでビルド・実行し、得点と操作列を確認しています。さらに [beam_search.test.cpp](../../tests/beam_search.test.cpp) では、独立した単純実装とのランダム比較により、コピー版・木上版、各選抜方式、chokudai、重複除去、展開数制限を検証します。時間上限0、評価中の時間切れ、深い操作列の復元も対象です。

TODOひな型は、通常・key別・全体＋key別と、それらのchokudai設定への差し替えについて構文・型を確認します。TODOの正しさを検証したものではありません。

この例題に対する各方式の速度比較や、他のライブラリに対する性能倍率は測定していません。
