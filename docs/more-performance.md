# SMAWK・Li Chao Tree・セグメント木・二部マッチングの高速化

比較する5ヘッダの基準実装はコミット `4381463` と同一です。前回までの高速化は [performance.md](performance.md) と [wavelet-performance.md](wavelet-performance.md) を参照してください。

## 変更内容

- **SMAWK**: 奇数行の最小列を補間に使う際、列の先頭から `std::find` を繰り返していた処理を一方向のカーソルに変更。行の最小列が対角線付近に並ぶ行列では内部探索が二乗時間になっていたが、変更後は線形時間になる。評価回数は以前から線形で、今回改善したのは値の評価以外の列探索。再帰を型が決まるlambdaに変更し、一時vectorの容量も事前に確保する。左端の最小列を返す規則を維持する。
- **LiChaoTree**: 同じ傾きは切片だけを比較して処理。残った直線が区間の両端で既存の直線に勝てない場合はそこで破棄する。不要な子ノードの生成と下位の走査を省き、挿入と取得を反復処理に変更する。整数座標の区間と、演算が型に収まるという従来の制約を維持する。
- **PersistentSegmentTree**: 構築時に必要なノード数を事前に確保する。複数回のbuildでは容量を幾何的に増やして再確保を抑え、古いrootを維持する。`get` を該当する子だけの反復処理に変更する。広い区間の `prod` への追加分岐は測定で効果が出なかったため採用せず、従来の走査を維持する。空区間は即座に単位元を返す。
- **DynamicSegmentTree**: `get` を該当する子だけの反復処理に変更し、未作成ノードでは単位元を返す。`prod` はクエリが片側に収まる場合、反対側の子の呼び出しを省く。空区間は即座に単位元を返す。非可換モノイドでも左から右の集約順序を維持する。
- **HopcroftKarp**: 最初に直接の増加を行い、それだけでマッチング数の上限に達した場合はBFSを省く。残りは最短の増加路までの層をBFSで作り、DFSが既に見た辺を各頂点のカーソルで管理する。BFSのqueue用配列を再利用する。追加メモリは左頂点数に比例し、辺の追加後の再実行と最小頂点被覆の取得も引き続き可能。

公開関数の引数・戻り値と、各ヘッダ先頭のGitHub URLコメントは維持している。Li Chao Treeでは不要なノードが増えなくなるため、内部のノード数は変わる。二部マッチングでは選ばれる辺や最小頂点被覆が変わる場合があるが、最大サイズ・被覆サイズは同じ。

## 測定結果

Intel Core Ultra 9 285H、GCC 15.2.0、`-std=c++17 -O2`。変更前後を順番に実行し、各ケース5回の中央値を採用。入力生成は計測対象外で、全ケースのチェックサムが一致した。

| ケース | 変更前 (ms) | 変更後 (ms) | 速度比 |
| --- | ---: | ---: | ---: |
| `smawk_diagonal_6000` | 3.006 | 0.035 | 87.01倍 |
| `smawk_diagonal_12000` | 11.818 | 0.074 | 159.56倍 |
| `smawk_diagonal_24000` | 46.102 | 0.210 | 219.39倍 |
| `smawk_ties` | 0.157 | 0.151 | 1.04倍 |
| `li_chao_random_add` | 31.381 | 1.999 | 15.70倍 |
| `li_chao_equal_slope_add` | 32.070 | 0.138 | 232.39倍 |
| `li_chao_active_add` | 17.855 | 13.538 | 1.32倍 |
| `li_chao_query` | 1.545 | 0.961 | 1.61倍 |
| `persistent_seg_build` | 4.416 | 0.573 | 7.71倍 |
| `persistent_seg_get` | 7.341 | 3.731 | 1.97倍 |
| `persistent_seg_prod` | 15.552 | 14.977 | 1.04倍 |
| `dynamic_seg_get` | 9.125 | 3.479 | 2.62倍 |

| `hopcroft_unbalanced` | 0.278 | 0.007 | 40.48倍 |

入力・計測範囲:

- SMAWK: `A[row,col]=(row-col)^2` の正方行列で最小列が対角線上にある。6000・12000・24000行でスケーリングを確認。tiesは24000行・列の全要素が同じ行列
- Li Chao Tree: 20万直線。randomはランダムな傾き・切片、equal_slopeはすべて同じ傾き、activeは `y=-2ix+i²` を `[0,200000)` 上に追加し、各直線が異なる整数点で最小になる。queryはrandomの構築済み木へ10万回の取得
- PersistentSegmentTree: 20万要素の構築、構築済み木への10万回のランダムな一点取得・区間和
- DynamicSegmentTree: `[0,200000)` 全点を代入した構築済み木への同じ10万クエリ。挿入は取得・集約の計測に含めない
- HopcroftKarp: denseは2000対2000の完全二部グラフ、sparseは30000対30000で左頂点ごとに7本のランダム辺と同番号の右頂点への辺、unbalancedは30000対4の完全二部グラフ。辺の生成は計測対象外で、各試行前にmatching配列を初期化する

速度比はこの環境と入力に限る。例えば同じ傾きの直線では追加を即座に終えられるが、すべての直線が必要なケースで同じ速度比になるわけではない。二部マッチングの結果数が左右の小さい側に達しない場合は、BFS・DFSによる増加路探索が必要。

## 正しさの検証

関連する既存5テストと追加の `more_performance_regressions.test.cpp` をコンパイル・実行。追加テストでは以下を確認する。

- SMAWK: 空・長方形・奇数行・列、Monge行列と素朴な全列探索の比較、同値時の左端、10万行の対角ケースと評価回数の上限
- Li Chao Tree: 幅1・非2冪・負座標、追加ごとの素朴な全直線評価との比較、同じ傾き、交点が整数上にある同値、すべての直線が必要になる入力のランダム追加
- 両セグメント木: 文字列連結による非可換な集約、空区間、未作成ノード、端点、ランダム更新、永続versionの分岐と古いrootの維持、複数回のbuild
- 二部マッチング: 小さなランダムグラフと全探索の比較、辺の逐次追加と再実行、平行辺・空の左右集合。より大きなグラフでもマッチングと同サイズの頂点被覆を確認し、全辺を被覆していることから最適性を検証。2000頂点を通る増加路も確認

追加テストは展開後のソースでも実行し、5ヘッダのGitHub URLコメントが残ることを確認する。AddressSanitizerとUBSanでも検証する。環境のptrace制約により、LeakSanitizerのみ `ASAN_OPTIONS=detect_leaks=0` で無効化する。
